# Kubernetes manifests (EKS)

Runs the backend on EKS. The frontend is not here: it is a static build served from S3 + CloudFront.

```text
k8s/
├── kustomization.yaml        # everything long-running; generates ConfigMaps; sets the ECR image names
├── domain.yaml               # the API hostname and frontend origin (copied in at build time)
├── namespaces.yaml           # campuscouriers-app, campuscouriers-messaging
├── app/
│   ├── config/               # each service's non-secret settings (<service>.env) -> generated ConfigMaps
│   ├── user-service.yaml     # fully commented reference; the other services follow the same layout:
│   ├── supplier-service.yaml #   ServiceAccount, Deployment, Service, HPA, PodDisruptionBudget
│   ├── credit-service.yaml
│   ├── order-service.yaml
│   ├── notification-service.yaml  # 1 pod only (live notifications), no HPA/PDB
│   ├── chat-service.yaml     # 1 pod only (live WebSockets), no HPA/PDB
│   ├── external-secrets.yaml # DB credentials, JWT keys, first admin, order<->credit key
│   ├── database-endpoints.yaml  # user-db, order-db, ... -> RDS endpoint (DNS aliases)
│   ├── ingress.yaml          # ALB: api.<domain>, routed by path
│   └── network-policies.yaml
├── messaging/
│   ├── kafka.yaml            # 3-broker KRaft StatefulSet with EBS volumes
│   ├── kafka-connect.yaml    # Debezium
│   ├── database-endpoints.yaml
│   ├── storageclass.yaml     # gp3 EBS volumes
│   ├── external-secrets.yaml # Debezium's DB credentials, from Secrets Manager
│   └── network-policies.yaml
├── platform/
│   └── cluster-secret-store.yaml  # tells External Secrets to read from AWS Secrets Manager
├── ops/                      # db-init: creates the per-service databases and users (applied, then deleted)
└── jobs/                     # one-off tasks, applied separately
    ├── order-migrate.yaml    # alembic upgrade head
    ├── user-bootstrap.yaml   # first administrator
    ├── supplier-seed.yaml    # supplier CSV import
    └── register-connectors.yaml
```

| compose.yaml | Kubernetes |
| --- | --- |
| a service | Deployment (pods) + Service (stable address) |
| `environment:` | ConfigMap (settings) + Secret (passwords, keys) |
| `ports: "8081:8080"` | Ingress (public) / Service (internal) |
| `user-db` container | RDS, reached through the `user-db` ExternalName alias |
| `kafka` container | StatefulSet with one persistent disk per broker |
| `connect-init`, `user-bootstrap` | Jobs |
| `restart: unless-stopped` | liveness probe + Deployment controller |
| (nothing) | HorizontalPodAutoscaler, PodDisruptionBudget, NetworkPolicy |

## Before you deploy

### Cluster add-ons (all installed by `terraform/infra`)
- **AWS Load Balancer Controller**: turns `ingress.yaml` into an ALB.
- **External Secrets Operator**: builds Kubernetes Secrets from AWS Secrets Manager (`app/external-secrets.yaml`, `platform/cluster-secret-store.yaml`).
- **metrics-server**: provides the CPU numbers the autoscalers (HPAs) use.
- **Amazon EBS CSI driver**: creates the EBS disks for Kafka.
- **VPC CNI with network policy enabled**: without it, NetworkPolicies are silently ignored.

### AWS resources
- **RDS for PostgreSQL** (`terraform/infra/rds.tf`): with `rds.logical_replication = 1` for Debezium. The per-service databases and users are created by the db-init Job (Deploy, step 2).
- **Secrets Manager**: DB passwords are generated by Terraform; the JWT keys and first admin are filled in by hand once (`terraform/README.md`, "Secrets").
- **ECR** (`terraform/infra/ecr.tf`): build and push the four service images with `./scripts/build-and-push.ps1`. It tags them with the git commit and updates `images:` in `kustomization.yaml` and `jobs/kustomization.yaml`; commit that change.
- **Domain** (`terraform/bootstrap/dns.tf`): Route 53 hosted zone + ACM certificate for `api.<domain>`; the certificate must show ISSUED. **external-dns** (`terraform/infra/external-dns.tf`) then creates the `api.<domain>` record pointing at the ALB by itself.

## Deploy

All Secrets come from AWS Secrets Manager through External Secrets: there is no `kubectl create secret` step.

```sh
# 1. Namespaces, and where secrets come from
kubectl apply -f k8s/namespaces.yaml -f k8s/platform/cluster-secret-store.yaml

# 2. Databases and users on RDS (once; again after rotating a DB password), then remove the
#    master password from the cluster
kubectl apply -k k8s/ops
kubectl wait --for=condition=complete job/db-init -n campuscouriers-ops --timeout=5m
kubectl logs job/db-init -n campuscouriers-ops
kubectl delete -k k8s/ops

# 3. Debezium connectors + script, straight from debezium/ (re-run after changing them)
kubectl create configmap debezium-connectors -n campuscouriers-messaging \
  --from-file=debezium/connectors --from-file=debezium/register-connectors.sh \
  --dry-run=client -o yaml | kubectl apply -f -

# 4. Everything long-running (preview first with: kubectl kustomize k8s)
kubectl apply -k k8s

# 5. One-off jobs: migrations, first admin, supplier seed, connector registration
kubectl apply -k k8s/jobs
kubectl get jobs -A -w
```

**Deploying a new order-service version with a new migration:** run the `order-migrate` Job first (delete the old finished Job if it still exists), wait for it to complete, then update the image.

## Check it works

```sh
kubectl get pods -n campuscouriers-app -o wide      # 2 pods per service, on different nodes
kubectl get pods -n campuscouriers-messaging        # kafka-0..2, kafka-connect
kubectl get hpa -n campuscouriers-app               # current vs target CPU, replica counts
kubectl get ingress api -n campuscouriers-app       # ADDRESS = the ALB's DNS name
kubectl describe ingress api -n campuscouriers-app  # events show ALB creation errors, if any

# Connector status (Connect's API is internal only)
kubectl port-forward -n campuscouriers-messaging svc/kafka-connect 8083:8083
curl localhost:8083/connectors?expand=status
```

## Demonstrating autoscaling

Login is CPU-heavy (password hashing), so it is a good load target. Use an account that exists, with the wrong password:

```sh
# terminal 1
kubectl get hpa user-service -n campuscouriers-app --watch
# terminal 2
hey -z 3m -c 40 -m POST -H "Content-Type: application/json" \
  -d '{"email":"<existing-user-email>","password":"wrong-password"}' https://api.<your domain>/auth/login
```

Replicas climb from 2 toward 5 as CPU passes 70%. About 5 minutes after the load stops, they drop back to 2 (`scaleDown.stabilizationWindowSeconds`).

PodDisruptionBudget demo: `kubectl drain <node> --ignore-daemonsets --delete-emptydir-data`. Kubernetes evicts pods one at a time and never leaves a service with zero ready pods.

## Notes
- **Changing settings:** edit `app/config/<service>.env` (or `domain.yaml`) and `kubectl apply -k k8s`. The ConfigMap gets a new hash-suffixed name, so the affected Deployments roll by themselves. Old ConfigMaps stay behind (harmless); clean up with `kubectl delete configmap -n campuscouriers-app <old name>`. **Secrets don't do this:** after a secret changes in Secrets Manager, environment variables only update on restart (`kubectl rollout restart deployment/<name> -n campuscouriers-app`, or `-n campuscouriers-messaging deployment/kafka-connect` for the Debezium logins); mounted files (the JWT keys) update by themselves.
- **notification-service and chat-service run exactly one pod.** Their live connections (Server-Sent Events, WebSockets) live in one pod's memory, and an event or message only reaches browsers connected to the pod that handled it. More pods would silently drop some live updates. Scaling them needs a shared broadcast (e.g. Redis pub/sub or PostgreSQL LISTEN/NOTIFY) in their code first.
- **RAG-service is not deployed** yet: nothing calls it, it has no login check, and each request spends Anthropic API credits. Add it once it's integrated and authenticated.
- **Login cookie:** the refresh token cookie is `SameSite=Strict` and `Secure`. It works when the frontend and API share a registrable domain (`app.example.com` and `api.example.com`), over HTTPS. It does **not** work between the default `*.cloudfront.net` address and the ALB's `*.elb.amazonaws.com` address: they count as different sites, and the ALB address has no certificate. Use your own domain, even for testing.
- **Internal-only routes:** `/api/reservations/**` (credit) is deliberately not in the Ingress: only order-service calls it, from inside the cluster, with the shared `order-credit-service-key`.
- **Kubelet probes and NetworkPolicies:** if pods fail their probes only after the policies are applied, check that the VPC CNI network policy agent allows traffic from the node. Kubelet probes come from the node's IP.
